# منصة التوعية بالأمن السيبراني — تطبيق الجوال (Flutter)

تطبيق أندرويد (وقابل لبناء iOS) لنفس مقترح المشروع: عند طلب المستخدم للوصول إلى
نظام مرتبط بصلاحية معيّنة، يقوم التطبيق بتوليد دورة تدريبية كاملة (بالذكاء
الاصطناعي أو بمحتوى احتياطي محلي)، ثم اختبار تقييم من ضمن سلسلة اختبارات، ثم
قرار وصول حتمي (اعتماد/محاولة أخرى/حظر) وفق عتبة النجاح الخاصة بحساسية كل
إدارة — تمامًا كما هو موصوف في `01_مقترح_المشروع.docx`.

اللغة الأساسية: **العربية**، مع تبديل فوري إلى **الإنجليزية** من الشريط العلوي
(RTL/LTR تلقائي).

## آخر التحديثات

- **قسم مدراء كامل**: تبويب "دخول كمدير" في شاشة الدخول يفتح لوحة تجمع بيانات
  كل الموظفين المسجَّلين على الجهاز (إحصاءات إجمالية، توزيع حسب الإدارة بأشرطة
  نسبية، وسجل قرارات على مستوى المؤسسة). تصميم مفاهيمي دون مصادقة فعلية بعد،
  كما هو الحال مع بقية المشروع.
- **تسجيل خروج**: زر ⏻ ثابت في الشريط العلوي لأي شاشة بعد الدخول (رئيسية،
  لوحة المتابعة، لوحة المدراء) يعيدك لشاشة الدخول.
- **الوضع الداكن/الفاتح**: زر 🌙/☀️ في كل شاشة، يُحفظ اختيارك محليًا ويُطبَّق
  عند إعادة فتح التطبيق.
- **سلسلة اختبارات حقيقية بدل اختبار ثابت**: كل دورة تولّد بنك من 8 أسئلة
  (بدلًا من 5 أسئلة ثابتة)، وكل محاولة اختبار — بما فيها محاولات إعادة
  التدريب العلاجي — تسحب 5 أسئلة عشوائية من البنك، فلا يتكرر نفس الاختبار
  حرفيًا بين المحاولات.
- **لوحة متابعة أوسع للموظف**: بطاقات إحصائية (الحالة الحالية، آخر درجة،
  المحاولات المستخدمة، عتبة النجاح) أعلى سجل القرارات.

## لماذا لا يوجد ملف APK جاهز داخل هذه الحزمة؟

بيئة إنشاء هذا المشروع لا تملك Android SDK / Gradle ولا اتصال إنترنت، لذلك
تم تسليم **الكود المصدري الكامل** بدلًا من ملف مُصرَّف. الأقسام أدناه توضح
طريقتين للحصول على APK حقيقي مثبَّت على جوالكم مباشرة — إحداهما لا تحتاج أي
أدوات على جهازكم إطلاقًا.

## الحصول على APK حقيقي على جوالك

### الطريقة الأسهل: بناء سحابي مجاني عبر GitHub Actions (من الجوال بالكامل، بلا Flutter وبلا حاسوب)

هذه الحزمة تحتوي على `.github/workflows/build-apk.yml` جاهز يبني APK حقيقي
تلقائيًا على خوادم GitHub المجانية. لا يلزمكم تثبيت أي شيء:

1. أنشئوا حسابًا مجانيًا على [github.com](https://github.com) إن لم يكن لديكم.
2. أنشئوا مستودعًا (Repository) جديدًا، ثم من "Add file → Upload files"
   ارفعوا **كل محتويات مجلد `flutter_app`** (بما فيها مجلد `.github` نفسه).
3. افتحوا تبويب **Actions** في المستودع — البناء يبدأ تلقائيًا (أو اضغطوا
   "Run workflow" يدويًا).
4. انتظروا 3-5 دقائق حتى تظهر علامة ✔ خضراء.
5. افتحوا التشغيلة المكتملة، انزلوا إلى قسم **Artifacts**، واضغطوا على
   `csa-platform-release-apk` لتحميل ملف الـ APK مباشرة إلى جوالكم.
6. افتحوا الملف المُحمَّل من إشعارات المتصفح لتثبيته (سيطلب أندرويد السماح
   بالتثبيت من "مصدر غير معروف" في أول مرة — إجراء طبيعي لأي APK خارج متجر
   Google Play).

كل هذه الخطوات يمكن تنفيذها من متصفح الجوال نفسه دون فتح حاسوب إطلاقًا.

> **بديل فوري بلا أي بناء إطلاقًا:** النسخة المرافقة على شكل PWA (ملف HTML
> واحد) تفتحونها من متصفح الجوال مباشرة ثم "إضافة إلى الشاشة الرئيسية"
> فتعمل كأيقونة مستقلة فورًا — بنفس المزايا (قسم مدراء، دارك مود، تسجيل
> خروج، سلسلة اختبارات) لكن دون تثبيت APK فعلي على النظام.

### الطريقة اليدوية: بناء محلي على حاسوبكم (إن كان لديكم Flutter مثبّتًا)

## المتطلبات

- تثبيت [Flutter SDK](https://docs.flutter.dev/get-started/install) (قناة stable)
- Android Studio أو `cmdline-tools` + Android SDK (يثبَّت غالبًا تلقائيًا مع Flutter)
- جهاز أندرويد فعلي أو محاكي (اختياري للتجربة قبل البناء النهائي)

## خطوات البناء (من الصفر حتى APK)

```bash
# 1) فك الضغط ثم الدخول لمجلد المشروع
cd flutter_app

# 2) توليد مجلدات المنصات (android/ios/...) — هذه الحزمة تحتوي فقط على lib/
#    و pubspec.yaml و assets/ لتبقى خفيفة؛ الأمر التالي يُنشئ البقية تلقائيًا
#    دون المساس بملفاتنا:
flutter create --platforms=android,ios --org com.kaust.csa .

# 3) تثبيت الحزم
flutter pub get

# 4) تشغيل تجريبي على جهاز/محاكي متصل
flutter run

# 5) بناء APK حقيقي للتثبيت المباشر (وضع تجريبي، بدون مفتاح توقيع مخصص)
flutter build apk --release

# الملف الناتج يكون هنا:
# build/app/outputs/flutter-apk/app-release.apk
```

انسخ `app-release.apk` إلى الهاتف وثبّته (فعّل "مصادر غير معروفة" مؤقتًا).

### بناء App Bundle لنشره على متجر Google Play

```bash
flutter build appbundle --release
# الناتج: build/app/outputs/bundle/release/app-release.aab
```
قبل النشر الفعلي على المتجر، يجب توقيع الحزمة بمفتاح إصدار خاص بكم
(راجع [توثيق التوقيع من Flutter](https://docs.flutter.dev/deployment/android#signing-the-app)).

## ربط توليد المحتوى بالذكاء الاصطناعي الفعلي

راجع `lib/services/ai_service.dart`. التطبيق يعمل بكامل وظائفه فورًا بدون أي
إعداد إضافي عبر **محتوى احتياطي محلي** (قوالب مرتبطة بمرجعي الضابط
`ECC-2:2024` و `TCC-1:2021`)، وهذا يضمن أن التطبيق قابل للتجربة والتقييم دون
أي اعتماد خارجي — تمامًا كما ينصّ المقترح على أن المنصّة "تعمل بالكامل داخل
شبكة معزولة دون أي اعتماد على خدمة خارجية".

لربطه بمحرّك الذكاء الاصطناعي الحقيقي (LLM المحلي + RAG على ضوابط الهيئة كما
في التصميم المفاهيمي)، مرّروا نقطة نهاية الـ backend الخاصة بكم (Oracle
APEX / PKG_AI_INTEGRATION) عند البناء:

```bash
flutter build apk --release \
  --dart-define=BACKEND_URL=https://your-backend.example/api/generate
```

⚠️ **لا تضعوا مفاتيح API مباشرة داخل كود التطبيق أبدًا** — أي سر مُضمَّن في
تطبيق موبايل قابل للاستخراج من ملف APK. البنية الصحيحة (والمطابقة للمقترح)
هي أن يتحدث التطبيق فقط إلى الـ backend الخاص بكم، والـ backend هو من
يتحدث مع النموذج داخل الشبكة المعزولة.

## بنية المشروع

```
lib/
  main.dart                 نقطة الانطلاق + تبديل اللغة والاتجاه
  theme.dart                الألوان والتنسيق الموحّد
  l10n/strings.dart         قاموس الترجمة عربي/إنجليزي
  models/
    department.dart         نموذج الإدارة/النظام/عتبة النجاح
    course.dart              نماذج الدرس، سؤال الاختبار، سجل القرار الثابت
  services/
    ai_service.dart          توليد الدورة (LLM أو محتوى احتياطي محلي)
    storage_service.dart     تخزين الحالة والسجل على الجهاز (SharedPreferences)
  screens/
    login_screen.dart        تسجيل الدخول (موظف/مدير) واختيار الإدارة
    home_screen.dart         الأنظمة والصلاحيات وحالة كل طلب
    course_screen.dart       عرض الدروس المولّدة خطوة بخطوة
    exam_screen.dart         اختبار عشوائي من سلسلة الاختبارات (5 من 8)
    result_screen.dart       النتيجة والقرار (اعتماد/محاولة أخرى/حظر)
    dashboard_screen.dart    لوحة متابعة الموظف (إحصاءات + سجل ثابت)
    admin_screen.dart        لوحة المدراء (إحصاءات المؤسسة + سجل شامل)
assets/data/departments.json بيانات الإدارات وعتبات النجاح (من المقترح)
```

## منطق سير العمل (مطابق للمقترح)

1. الموظف يختار إدارته ويطلب الوصول إلى النظام المرتبط بها.
2. يتولّد محتوى تدريبي (4 دروس) مرتبط بنصّ ضوابط الهيئة الوطنية بالضبط.
3. بعد إتمام الدروس، اختبار من 5 أسئلة متعددة الخيارات.
4. تُحسب الدرجة وتُقارن بعتبة النجاح الخاصة بحساسية الإدارة:
   - التقنية/الذكاء الاصطناعي والتقاضي: **90%** (حرجة)
   - القانونية، الموارد البشرية، المالية: **85%** (عالية)
   - المشتريات، الإمداد، العمليات: **80%** (متوسطة)
5. عند النجاح → اعتماد فوري للوصول. عند الإخفاق → حتى 3 محاولات مع تدريب
   علاجي مستهدف للضوابط التي أخفق فيها الموظف تحديدًا، ثم حظر يتطلب مراجعة
   يدوية بعد المحاولة الثالثة.
6. كل قرار يُسجَّل في سجل ثابت (لا يُعدَّل ولا يُحذَف) لأغراض التدقيق وفق
   NCA ECC / NIST CSF 2.0 / ISO 27001.
